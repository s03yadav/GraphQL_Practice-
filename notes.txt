++++++++++++++++++++++++++++++++ Day 1 Update ++++++++++++++++++++++++++++++++

**What is dotenv library?**

=> `dotenv` is an npm package that helps store configuration values and sensitive information outside JavaScript code.

=> Code: `require('dotenv').config();`

**What is Apollo Server?**

=> Apollo Server is responsible for receiving GraphQL requests, validating queries against your schema, executing resolvers and returning results as JSON.

**TypeDefs:**

=> Defines your GraphQL schema. `typeDefs` defines the structure of your API.

=> The syntax used here is called GraphQL Schema Definition Language (SDL).

Example:

```javascript
const typeDefs = `
    type Query {
        totalPosts: Int!
    }
`;
```

- `type` = Defines a GraphQL type.
- `Query` = Root type for reading data.
- `totalPosts` = Field that the client can request.
- `Int` = Integer data type.
- `!` = Value cannot be null.

**Resolvers:**

=> Resolvers are JavaScript functions that tell GraphQL how to retrieve or calculate the value of a field.

Example:

```javascript
const resolvers = {
    Query: {
        totalPosts: () => {
            return 52;
        }
    }
};
```

**Creating an Apollo Server:**

```javascript
const apolloServer = new ApolloServer({
    typeDefs,
    resolvers
});
```

**Integrating Apollo Server with Express**

=> Created an asynchronous function named `startServer()` to integrate Apollo Server with the Express application.

=> Used `async/await` to ensure Apollo Server starts before registering its middleware.

=> Registered Apollo Server middleware with Express using `expressMiddleware(server)`.

=> Used `app.use()` to configure the GraphQL endpoint at `/graphQL`.

=> Registered a normal Express GET route using `app.get('/')`.

=> Started the Express application using `app.listen()` on the specified PORT.

**Main Function:**

```javascript
async function startServer() {

    // Start Apollo Server
    await server.start();

    // Register Apollo middleware
    app.use(
        '/graphQL',
        cors(),
        express.json(),
        expressMiddleware(server)
    );

    // Start Express Server
    app.listen(process.env.PORT);
}

startServer();
```

**Concepts Learned:**

1. `async/await` – Handling asynchronous operations.
2. `app.use()` – Registering middleware in Express.
3. `cors()` – Allowing cross-origin requests.
4. `express.json()` – Parsing incoming JSON request bodies.
5. `expressMiddleware()` – Connecting Apollo Server with Express.
6. `app.listen()` – Starting the Express HTTP server.

**Modular File Structure for GraphQL**

=> Created a separate file distribution for GraphQL `typeDefs` and `resolvers` to make the project more organized and maintainable.

=> Used the following libraries:

- `@graphql-tools/merge`
- `@graphql-tools/load-files`

**Folder Structure:**

```text
graphql_project_ud/
│
├── resolvers/
│   └── getuser.js
│
├── typeDefs/
│   ├── address.js
│   └── user.js
│
└── server.js
```

**Concepts Learned:**

1. `loadFiles()` – Automatically loads multiple schema or resolver files from a specified directory.

2. `mergeTypeDefs()` – Combines multiple GraphQL type definitions into a single schema.

3. `mergeResolvers()` – Combines multiple resolver objects into a single resolver object.

**Example:**

```javascript
const { mergeTypeDefs, mergeResolvers } =
    require('@graphql-tools/merge');

const { loadFiles } =
    require('@graphql-tools/load-files');

const path = require('path');

// Load all typeDef files
const def_File = await loadFiles(
    path.join(__dirname, './typeDefs')
);

// Load all resolver files
const resolver_Files = await loadFiles(
    path.join(__dirname, './resolvers')
);

// Merge all typeDefs
const typeDefs = mergeTypeDefs(def_File);

// Merge all resolvers
const resolvers = mergeResolvers(resolver_Files);
```

**Important Learning:**

=> Instead of importing every schema and resolver file manually, `loadFiles()` automatically loads them from their respective folders.

=> `mergeTypeDefs()` and `mergeResolvers()` combine the loaded files, allowing Apollo Server to receive a single consolidated schema and resolver structure.

**MongoDB Atlas Connection using Mongoose**

=> Connected the Node.js application with MongoDB Atlas using a connection URL stored in the `.env` file.

=> Installed and used the `mongoose` library to establish a connection between the application and MongoDB Atlas.

=> Created a separate file named `connection.js` to handle database connectivity, keeping database logic separate from the main `server.js` file.

**Connection Function:**

```javascript
async function connect(URL) {
    try {
        const db = await mongoose.connect(URL);
        return db;
    } catch (err) {
        console.log(err);
        throw err;
    }
}

module.exports = connect;
```

**Concepts Learned:**

1. **Mongoose:** An ODM (Object Data Modeling) library that allows Node.js applications to interact with MongoDB using JavaScript objects and schemas.

2. **mongoose.connect():** Establishes a connection between the Node.js application and MongoDB using the provided connection URL.

3. **Async/Await:** Used to handle the asynchronous database connection process.

4. **Try/Catch:** Handles errors that may occur while establishing the database connection.

5. **Environment Variables:** Stored the MongoDB Atlas connection string in `.env` using `CLOUD_DB` to keep sensitive connection details outside the source code.

**Server Integration:**

=> Imported the `connect()` function into `server.js`.

=> Called `connect(process.env.CLOUD_DB)` to establish the database connection.

=> Used `.then()` to start the Express server only after successfully connecting to MongoDB Atlas.

=> Used `.catch()` to handle database connection errors.

**Important Learning:**

The Express server starts listening for incoming requests only after a successful database connection. This ensures that the application does not start accepting requests when its database connection has failed.

**Introduction to GraphQL Mutations**

=> Learned about GraphQL Mutations, which are used to perform operations that modify data on the server.

=> While Queries are used to fetch or read data, Mutations are used to create, update or delete data.

**Difference between Query and Mutation:**

1. Query – Used to retrieve existing data.
2. Mutation – Used to modify existing data.

**1. Defining Mutation in TypeDefs**

=> Added a `Mutation` root type inside `user.js` to define an operation named `newUser`.

=> `newUser` accepts name, address, email and mobile as arguments and returns a User object.

**user.js**

```graphql
type Mutation {
    newUser(
        name: String!,
        address: AddressInput!,
        email: String!,
        mobile: String!
    ): User!
}
```

**2. Understanding GraphQL Input Types**

=> Created a custom input type named `AddressInput` inside `address.js`.

=> Input types are used to accept structured objects as arguments in GraphQL queries and mutations.

**address.js**

```graphql
input AddressInput {
    houseNumber: Int!
    buildingName: String!
    Area: String!
    pincode: Int!
    City: String!
    State: String!
}
```

**Concepts Learned:**

1. `type Mutation` – Defines the root type for data-modifying operations.
2. `input` – Defines a custom input object that can be passed as an argument to a Query or Mutation.
3. `AddressInput!` – Specifies that the address argument must be provided and cannot be null.
4. `User!` – Specifies that the mutation must return a non-null User object.

**3. Creating Mutation Resolver**

=> Created a `newUser()` resolver function inside `getuser.js`.

=> The function receives the arguments provided by the client and creates a new User object.

=> Used `dummyUsers.length + 1` to generate a new user ID.

=> Used `dummyUsers.push()` to add the newly created user to the existing dummy users array.

=> Returned the newly created User object as the mutation response.

**getuser.js**

```javascript
// Mutations
function newUser(parent, args) {

    console.log(args);

    const User = {
        id: dummyUsers.length + 1,
        name: args.name,
        address: args.address,
        email: args.email,
        mobile: args.mobile,
    };

    dummyUsers.push(User);

    return User;
}

const resolvers = {
    Query: {
        getUsers
    },
    Mutation: {
        newUser
    }
};
```

**Understanding Resolver Arguments:**

=> `parent` – Contains the result returned by the parent resolver.

=> `args` – Contains the arguments passed by the client while executing the mutation.

=> In this example, `args` contains name, address, email and mobile.

**4. Executing Mutation in Apollo Server**

=> Tested the `newUser` mutation through the Apollo Server interface.

=> Passed user details and a nested address object as mutation arguments.

**Mutation Operation:**

```graphql

            Area: "Maninagar"
```

**Understanding the Mutation Operation:**

1. `mutation` – Indicates that we are performing a data-modifying operation.
2. `newUser` – Calls the mutation defined inside the Mutation type.
3. `name`, `address`, `email`, `mobile` – Input arguments passed to the resolver.
4. `address` – Accepts a nested object using the `AddressInput` type.
5. `{ id name email }` – Specifies which fields should be returned in the response.

**Important Learning:**

=> GraphQL Mutations allow clients to perform Create, Update and Delete operations.

=> Input types help pass structured and reusable objects to mutations.

**Introduction to Apollo Client (Client-Side GraphQL)**

=> Learned how to integrate Apollo Client into a React application to communicate with the GraphQL API created using Apollo Server.

=> Apollo Client helps the frontend send GraphQL Queries and Mutations to the backend, manage responses, and maintain a local cache of fetched data.

**1. Setting Up Apollo Client**

=> Created an Apollo Client instance using `ApolloClient({})`.

=> Configured the client using `HttpLink` and `InMemoryCache`.

**Example:**

```javascript
import { ApolloClient, HttpLink, InMemoryCache } from '@apollo/client';

const httpLink = new HttpLink({
    uri: 'http://localhost:9000/graphQL'
});

const client = new ApolloClient({
    link: httpLink,
    cache: new InMemoryCache()
});
```

**Understanding the Configuration:**

1. `ApolloClient({})` – Creates an Apollo Client instance that manages communication between the React frontend and GraphQL backend.

2. `HttpLink` – Establishes the HTTP connection through which GraphQL requests are sent to the Apollo Server.

3. `uri` – Specifies the URL of the GraphQL endpoint where the backend server receives requests.

4. `link: httpLink` – Connects the HTTP link to Apollo Client so it knows where and how to send GraphQL operations.

**Why do we use HttpLink?**

=> HttpLink acts as a communication layer between Apollo Client and Apollo Server.

=> Whenever a GraphQL Query or Mutation is executed, HttpLink sends the operation to the specified GraphQL endpoint using HTTP.

**2. InMemoryCache**

=> Used `new InMemoryCache()` to create a cache system for Apollo Client.

=> InMemoryCache stores previously fetched GraphQL data in the browser's memory.

**Why do we need InMemoryCache?**

1. Avoids unnecessary API requests when previously fetched data is available in the cache.
2. Improves application performance by reducing network requests.
3. Makes previously fetched data available more quickly.
4. Helps Apollo Client manage and update GraphQL data locally.

**Example:**

```javascript
const client = new ApolloClient({
    link: httpLink,
    cache: new InMemoryCache()
});
```

**Important Learning:**

=> InMemoryCache is a client-side cache, not a permanent database.

=> Its data is stored in memory and is generally lost when the application is refreshed or restarted.

**3. ApolloProvider**

=> Used `ApolloProvider` to make the configured Apollo Client available throughout the React application.

=> Wrapped the main React application component inside ApolloProvider.

**Example:**

```javascript
import { ApolloProvider } from '@apollo/client/react';

ReactDOM.createRoot(document.getElementById('root')).render(
    <ApolloProvider client={client}>
        <App />
    </ApolloProvider>
);
```

**Why do we use ApolloProvider?**

1. It provides the Apollo Client instance to all nested React components.
2. Allows components to execute GraphQL Queries and Mutations without manually passing the client through props.
3. Makes Apollo Client accessible through hooks such as `useQuery` and `useLazyQuery`.

**4. Understanding gql**

=> Used `gql` to define GraphQL Queries inside the React application.

=> `gql` is a GraphQL template literal tag that parses GraphQL query strings into DocumentNode objects that Apollo Client can understand.

**Example:**

```javascript
import { gql } from '@apollo/client';

const GET_USERS = gql`
    query {
        getUsers {
            id
            name
        }
    }
`;
```

**Important Learning:**

=> `gql` allows us to write GraphQL operations directly inside JavaScript files.

=> The resulting query can be passed to Apollo Client hooks such as `useQuery` and `useLazyQuery`.

**5. useQuery Hook**

=> Learned about the `useQuery` hook, which is used to execute GraphQL Queries inside React functional components.

=> It automatically executes the query when the component renders.

**Example:**

```javascript
import { gql } from '@apollo/client';
import { useQuery } from '@apollo/client/react';

const GET_USERS = gql`
    query {
        getUsers {
            id
            name
        }
    }
`;

const Users = () => {

    const { loading, error, data } = useQuery(GET_USERS);

    if (loading) {
        return <h2>Loading...</h2>;
    }

    if (error) {
        return <h2>Error: {error.message}</h2>;
    }

    return (
        <div>
            {data.getUsers.map((user) => (
                <h3 key={user.id}>{user.name}</h3>
            ))}
        </div>
    );
};

export default Users;
```

**Understanding useQuery Parameters:**

The `useQuery()` hook returns an object containing different properties.

1. `loading` – A boolean value that indicates whether the GraphQL request is currently in progress.

2. `error` – Contains error information if something goes wrong while executing the GraphQL operation.

3. `data` – Contains the response data returned by the GraphQL server after successful execution.

**Important Learning:**

=> `useQuery` automatically executes the GraphQL query when the component renders.

=> It also manages loading states, errors and returned data, reducing the need to manually manage API requests using `useEffect` and `useState`.

**6. useLazyQuery Hook**

=> Learned about the `useLazyQuery` hook, which is used when we want to execute a GraphQL Query only after a specific user action or event.

=> Unlike `useQuery`, it does not automatically execute the query when the component renders.

**Example:**

```javascript
import { gql } from '@apollo/client';
import { useLazyQuery } from '@apollo/client/react';

const GET_USERS = gql`
    query {
        getUsers {
            id
            name
        }
    }
`;

const LazyQuery = () => {

    const [fetchData, { loading, error, data }] =
        useLazyQuery(GET_USERS);

    return (
        <div>
            <button onClick={() => fetchData()}>
                Fetch Users
            </button>

            {loading && <h2>Loading...</h2>}

            {error && <h2>{error.message}</h2>}

            {data && data.getUsers.map((user) => (
                <h3 key={user.id}>{user.name}</h3>
            ))}
        </div>
    );
};

export default LazyQuery;
```

**Understanding useLazyQuery Parameters:**

Unlike `useQuery`, `useLazyQuery` returns an array containing two elements:

1. `fetchData` – A function that manually triggers the GraphQL Query whenever required.

2. Query Result Object – Contains the following properties:

   - `loading` – Indicates whether the query is currently executing.
   - `error` – Contains error information if the query fails.
   - `data` – Contains the response received from the GraphQL server.

**Difference Between useQuery and useLazyQuery:**

| useQuery | useLazyQuery |
|---|---|
| Executes automatically when the component renders. | Executes only when its trigger function is called. |
| Does not require a separate trigger function. | Returns a function to trigger the query manually. |
| Useful when data is required immediately. | Useful when data is required after a user action. |
| Example: Loading a user list on page load. | Example: Fetching user details after clicking a button. |

**Important Learning:**

=> Both hooks are used to execute GraphQL Queries in React functional components.

=> `useQuery` is suitable when data needs to be fetched automatically.

=> `useLazyQuery` is suitable when we want control over when the query gets executed.
